# Надёжность, проверка и безопасная разработка

## Инициализация

До запуска основного цикла проверяйте наличие периферии, тип, обязательные методы, размер экрана, доступность файлов и допустимость настроек.

## Во время работы

- Используйте `pcall` для ожидаемых ошибок внешних устройств.
- Вместо циклов максимальной частоты применяйте ожидание событий или ограниченный `sleep`.
- Предусматривайте отключение выходов при штатной остановке.
- Закрывайте открытые файлы.
- Проверяйте сообщения от модемов и HTTP.
- Устанавливайте тайм-ауты и ограничивайте количество повторов.
- Разделяйте интерфейс и управляющую логику.
- Избегайте больших пакетов и постоянной полной перерисовки дисплея.

## Безопасный ввод-вывод

Не выполняйте скачанный Lua без проверки. Считайте сетевые данные и файлы конфигурации недоверенными. Не храните реальные токены или пароли в примерах. Протоколы Rednet и ID компьютеров не являются криптографической аутентификацией.

## Матрица тестов

| Область | Сценарии |
| --- | --- |
| Запуск | Нет периферии, неправильный тип, нет файла |
| Сеть | Потерян модем, испорчен пакет, тайм-аут, дубликат |
| Интерфейс | Изменение размера, маленький экран, некорректные координаты |
| Математика | Нулевое расстояние, переход через 180°, малое `dt`, насыщение |
| Жизненный цикл | Перезапуск, остановка, отключение устройства |

## Статус проверки

Различайте **выполнено и пройдено**, **выполнено с ошибкой**, **проверено только статически** и **не проверено**. Анализ текста не подтверждает запуск внутри Minecraft.
