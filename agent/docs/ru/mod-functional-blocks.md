# GOCODE: функциональные блоки модпака 6.9.3 без графики

**Точные версии подтверждены JAR из модпака:** Minecraft 1.21.1 NeoForge, Create 6.0.10, Aeronautics 1.3.2 (с вложенным Create: Simulated 1.3.2), Create Propulsion: Simulated 1.1.5, Synaxis 1.5.0, SynaxisPlus 1.0.5, NeoPeripheral 1.4ve, Aeroworks 1.5.0, AeroEngineering 1.3.0.

Программа считывает `.nbt` Create или Sable Photomancy, строит геометрию из реальных блоковых координат, прикрепляет известные функциональные блоки к физическому телу и исполняет их логику в **текстовом симуляторе**. Числовой вывод содержит скорость, координаты, углы, силы, моменты, ресурс, вызовы CC и список недостаточно реализованных функций.

**Проверенные особенности:**

- Create Propulsion: Simulated: варианты обычных, ионных, творческих, векторных, жидкостных и твёрдотопливных двигателей; управление мощностью через CC/redstone; исходные методы периферии; применение силы в конкретной точке для реального момента `T=(point-center)×force`; вспомогательные блоки (реакционное колесо, tilt adapter, redstone transmission).
- Aeronautics 1.3.2: пропеллеры с формулой `config_thrust * direction_independent_speed`, разгон ротора с коэффициентом `0.15` за тик, стандартные значения тяги для малых пропеллеров `1.0`. Тяга подшипника с парусами `sail_power^1.5 * speed * 0.2` (формула получена из реального JAR). Горелка и паровой клапан подключаются как настраиваемые модели силы с явно указанной приблизительностью.
- Synaxis 1.5.0: динамические моторы (`setTarget` в радианах, `setPID`), jet (`setTrust` с буквальным написанием API), заслонки, якоря, сопротивления кинетике, гидравлика, propeller и jet rudder. Механика шарниров и аэродинамики пока приближённая.
- Create: Simulated: swivel bearing, analog transmission, 16 цветных переносных двигателей; доступное состояние/RPM и объявленный реальный read-only контракт периферии. **Кинетическая сеть Create и перегрузка по stress пока не реализованы.**
- Aeroworks: механические и пошаговые сервоприводы; AeroEngineering: части двигателей/сопла с явно задаваемой тяговой моделью; Create: speed controller.

Для несовместимых по версии либо пока не реализованных блоков симулятор выдаёт `unresolved`, а не выдумывает результаты. Реестр `agent/sim/mod_devices_manifest.json.gz` содержит реальные ID блоков из JAR, SHA-256 самих модов, названия моделей и список неохваченных блоков. В текущей версии физический API и методы части периферий проверены исходным кодом и декомпиляцией байткода, **но полноценный Sable/Rapier, Synaxis Cimulink, Create stress network и все функции модпака не скопированы.**

## Использование

```bash
python3 -m unittest discover -s agent/tests -p 'test_*.py'
python3 -m agent.sim.mod_cli agent/scenarios/mod_blocks.json --out agent-results/mod_blocks.json
```

Для настоящего чертежа:

```bash
python3 -m agent.sim.mod_cli agent/scenarios/mod_blocks.json --schematic path/to/ship.nbt --out agent-results/ship.json
```

В JSON сценарии можно выполнять `advance`, `call`, `attach`, `detach`, `redstone` и `rpm`. Ключи периферии зависят от фактического расположения блоков чертежа, поэтому для другого `.nbt` нужно изменить список команд. Обязательно указывайте массу, если она известна, и максимальную тягу/потребление топлива по реальной конфигурации мода: отсутствующие значения нельзя молча заменять произвольными.

Исходный Python-код и Lua-тестовая среда CraftOS пока не синхронизированы общим полноценным планировщиком. Для точного повторения игры необходимы эталонные трассы и нативные алгоритмы столкновений/суставов. Дополнительные спецификации в [English reference](../en/mod-functional-blocks.md).

## Полный каталог модпака

Сканер `agent/scripts/catalog_modpack_rar.py` обработал весь RAR пользователя: **218 слоёв JAR** (в том числе вложенные), **11 149 уникальных блоковых ID**. У **51 блока** имеется тестовая модель: часть моделей содержит воспроизведённые формулы, часть — только состояние или приближённую механику. Остальные блоки отмечены как неподдерживаемые — даже если они присутствуют в NBT чертеже.

Каталог `agent/sim/mod_devices_manifest.json.gz` хранит `blockstates` в компактном виде `[block_id, index_of_jar,...]`; поле `device_models` указывает только подключённые классы. JAR-файлы в GitHub не загружаются. Для повторного сканирования:

```bash
python3 -m agent.scripts.catalog_modpack_rar /path/to/modpack.rar --out agent/sim/mod_devices_manifest.json.gz
```
