# Headless-сервер с настоящим Sable

Этот режим запускает настоящий dedicated server Minecraft 1.21.1 на NeoForge 21.1.248 с оригинальным Sable 2.0.5 и обычными JAR модпака. Формулы Sable здесь не переписываются.

Серверный мод из `agent/headless` выполняет ограниченный JSON-сценарий обычными командами сервера и после завершённых игровых тиков записывает для всех конструкций Sable координаты, ориентацию, масштаб, линейную и угловую скорость, массу Sable, центр массы и мировые границы. Python-запускатель создаёт отдельную серверную папку, копирует конфигурации, считает SHA-256 каждого активного JAR и останавливает сервер после теста.

## Запуск в Windows

```powershell
python agent/scripts/run_headless_sable.py agent/headless/scenarios/stone_drop.json `
  --instance "C:\path\to\ElyPrismLauncher\instances\6.9.3" `
  --gradlew "C:\path\to\neoforge-project\gradlew.bat" `
  --java-home "C:\path\to\jdk-21" `
  --mode full
```

Запускатель намеренно принимает только version-pinned основу `6.9.3`. `--mode minimal` загружает только Sable для диагностики. `--mode full` передаёт NeoForge все серверные `.jar` этого инстанса. Чисто клиентские renderer/UI-файлы из `server-excluded-mods.txt` и файлы `.disabled` не загружаются: они не участвуют в dedicated-server физике. Мир, логи, копии конфигов, хеши модов и JSON-телеметрия сохраняются в `agent-results/` и не попадают в Git.

Параметр `--world "C:\path\to\saves\world"` вместе с `record_existing_world.json` копирует существующий мир в изолированный сервер и записывает уже сохранённые конструкции Sable. Перед копированием следует закрыть клиент, чтобы `level.dat`, region-файлы и хранилище Sable относились к одному сохранению. Исходный мир не изменяется.

Сценарий `stone_drop.json` использует настоящие команды `fill` и `sable assemble area`. Поэтому сборка конструкции, MassTracker, формы блоков, server tick, block entity модов и Java pipeline Sable выполняются production runtime. В режиме `minimal` Sable загружает упакованный в нём нативный Rapier. В полной сборке 6.9.3 мод `taov_core` намеренно заменяет эту библиотеку своей Sable-совместимой версией; сохранение этой замены необходимо для воспроизведения реального модпака, а не чистого Sable отдельно.

## Граница точности

Успешный прогон подтверждает поведение именно указанных хешей JAR, скопированных конфигов, мира и команд. Он не является вечной гарантией полного совпадения с другим клиентским миром, иными datapack, конфигурацией или версиями модов. Для точного повтора конкретного мира следует использовать копию его сохранения, server config и datapack при неизменном манифесте модов.

`run-summary.json` содержит `runtime_error_count` и строки ошибок server log. Успешная проверка движения не скрывает ошибки загрузки модов или datapack; перед подтверждением поведения конкретного блока эти диагностические строки необходимо проверить.

Реальная проверка полной сборки 6.9.3 загрузила 112 серверных JAR и 168 mod ID. Конструкция Sable из двух блоков получила массу 4.0, упала примерно с Y=200.49 до Y=42.50 и после 240 тиков имела нулевую линейную скорость. При этом журнал обнаружил существующие ошибки данных модпака — главным образом необязательные loot table с отсутствующими объектами и устаревшие ID блоков в physics properties. Они остаются в отчёте и не превращаются в ложное утверждение, что проверено поведение всех модов.
