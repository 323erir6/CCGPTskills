# Оригинальный Sable Rapier 2.0.5 без графики через JNI

**Состояние:** нативный физический решатель подключён и протестирован; **полная эквивалентность Minecraft и работы модовых блоков пока не подтверждена**.

В `agent/native/src/` находится исходный код небольшого Java/JNI-моста. Python-модуль `agent/sim/native_rapier.py` извлекает **оригинальную** библиотеку Rapier из вашего JAR Sable 2.0.5, компилирует Java-код и использует текстовый интерфейс. Мод JAR и бинарники не добавляются в GitHub. Поддерживаются Windows/Linux/macOS на x86_64, нужен Java JDK 21 и Python.

Источники: [Sable 2.0.5](https://github.com/ryanhcode/sable/tree/mc1.21.1-2.0.5-neoforge), [форк Rapier на конкретном коммите](https://github.com/ryanhcode/rapier/tree/38e92f117590862481a53df6fc69a5d893e29186).

Настоящий движок выполняет `initialize`, `createSubLevel`, `newVoxelCollider`, `addChunk`, `setMassProperties`, `applyForceAndTorque`, `step`, вычисляет линейные/угловые скорости, физические контакты и возвращает координаты контакта через `clearCollisions`. Для сопоставления используется обычный текстовый JSON.

## Проверенный результат

- Падение одиночного вокселя на слой грунта с поверхностью Y=168 в оригинальном движке: центр остановился около **Y=168.497**, скорость стала нулевой.
- Расчёт загруженной ракеты по 6 блокам с нативным решателем, но **приближёнными модовыми силами и формами блоков**: первый зарегистрированный нативный контакт при **t=14.825 с**, контактная точка около **(0,168,3374)**, центр масс около **(-0.709,168.713,3373.365)**.
- Повторный запуск на той же платформе дал такой же результат.

**Это всё ещё не точный прогноз Minecraft.** Для форм блоков на данном этапе используются полные кубы; необходимо извлечь реальные `VoxelShape`, классификацию `Face/Edge/Corner/Interior`, массы Sable и исходные настройки конфигурации. Тяга двигателя и силы парусов задаются отдельным адаптером по известным формулам, а не вызовами игрового мода. Сам контактный решатель и реакция вращения — действительно оригинальный Rapier. При изменении классификации контактных вокселей (`Face` вместо `Edge`) в тесте столкновения могли отсутствовать, поэтому этот параметр особенно важно проверять в реальной игре.

## Запуск

```sh
python -m pip install lz4 numpy scipy
python -m agent.sim.native_rapier --jar /path/to/sable-neoforge-1.21.1-2.0.5.jar --smoke --output agent-results/native-smoke.json
python -m agent.sim.native_rocket rszo_rocket_v0.nbt --jar /path/to/sable-neoforge-1.21.1-2.0.5.jar --max-seconds 60 --out agent-results/native-rocket.json
```

В Windows замените `python` на `py` и укажите свой путь к JAR. Нужен установленный JDK 21 для `javac` и `java`.

Исходные данные и нативная библиотека не выкладываются в репозиторий. Исполнять такой код следует только из доверенного модпака и проверенного `.nbt`.

Для реальной 100%-совместимой физики требуется **полноценный headless NeoForge dedicated server** с установленными модами и тестовым агентом, который загружает NBT, инициирует двигатели и записывает траекторию. Альтернатива — полностью воспроизвести игровой стек реестров, генерации физических форм и вызовов сил; только подключение `.so` не заменяет Java-логику Create и аддонов.
